# /마감 — 닫는다

## Use When

세션 종료 · 작업 완결 선언 전 · "문서 업데이트" 요청. **착수 직후나 작업 도중에는 부르지 않는다** —
이 스킬은 커밋까지 하므로 중간에 부르면 미완성이 트리에 박힌다.

## Steps — 절차 (순서 고정)

### 1. 게이트

```bash
npm test && npm run build && npm run lint
```

**실패하면 마감하지 않는다.** 고치거나, 못 고치면 미결로 남기고 이유를 적는다.

### 2. 증거 확인

이번 세션에 동작을 바꿨는가?

- 바꿨는데 **실제로 돌려서 확인 안 했다면 완료가 아니다.** 확인하거나 미완으로 남긴다.
- 확인했으면 `docs/evidence/YYYY-MM-DD/<주제>.md` 로 남긴다(**날짜가 폴더**) — 무엇을 어떻게
  확인했고, **확인하지 않은 범위**까지 적는다.

### 3. 얇은 문서 갱신

- `docs/status/PROJECT-STATUS.md` — 완료·다음 걸음·블로커만. 상세는 evidence로 보낸다.
- 갭 목록이 있으면 — 닫힌 것 CLOSED, 새로 발견한 것 OPEN 추가
- 결정을 했으면 결정 로그에 — 결정·이유·기각한 대안

### 4. 완료 판정

셋 중 하나로 정한다. **증거가 없으면 자동으로 `not-ready`다.**

| 판정 | 뜻 |
|---|---|
| `not-ready` | 검증 안 됨 또는 게이트 레드. 완료로 적지 않는다 |
| `ready-for-review` | 검증했으나 남은 리스크가 있다 |
| `ready-to-share` | 검증 끝, 남에게 보여도 된다 |

함께 적을 것 — **실제로 실행한** 검증 명령(적기만 한 것 금지) · 바뀐 문서와 이유 ·
**아직 확인 못 한 가정** · 남은 리스크.

### 5. 회고 (3문 — 답 없으면 "없음")

각 답이 **파일 한 줄로 안 떨어지면 적지 않는다.** 감상은 다음 세션에 아무것도 안 남긴다.

1. **반복한 수작업** → 스킬·스크립트로 자산화
2. **틀렸다가 되돌린 것** → 함정·규칙 한 줄로
3. **다음 세션이 다시 찾아야 할 것** → 배턴·문서로

"토큰 아끼자"는 답이 아니다. **같은 답을 더 싸게 얻을 길이 있었나**로 묻는다 —
검증을 깎는 결론은 회고 산출이 될 수 없다.

### 6. 핸드오프 캡슐

다음 세션이 **바로 이어받을 수 있게** 넷을 적는다.

1. **시작 지점** — 다음에 열 문서 또는 파일 경로. **실제 존재하는 경로여야 한다.**
2. **먼저 읽을 것 1~3개** — 그 이상 적지 않는다
3. **막힌 것과 미결 결정** — 왜 막혔는지까지
4. **다시 시작할 때 돌릴 첫 명령**

기록 위치는 `docs/status/PROJECT-STATUS.md`. 막혀서 중단할 때도 **안전한 다음 행동**을 남긴다.

### 7. 커밋

**게이트가 green 이고 4번 판정이 `not-ready` 가 아니면 커밋한다.** 승인을 따로 묻지 않는다 —
마감했는데 안 커밋된 상태가 남으면 다음 세션이 남의 작업과 섞인 트리를 받는다.

- **커밋 전에 `git status --short` 를 보고 범위를 보고한다.** 이번 세션이 안 건드린 파일이
  섞여 있으면 **개수와 폴더를 말한 뒤** 커밋한다 — 숨기지 않는다
- **메시지는 한국어**로, 최근 커밋의 문체를 따른다
- **푸시는 안 한다.** 커밋은 되돌릴 수 있고 푸시는 밖으로 나간다 — 푸시는 따로 명령받는다
- 기본 브랜치(`main`) 위면 **브랜치를 먼저 딴다**
- 아직 `git` 저장소가 아니면 그 사실을 알린다

**커밋하지 않는 경우** — 게이트 레드 · 판정 `not-ready` · 이번엔 하지 말라는 지시.

## Verify

- 게이트를 **실제로 돌렸고** green인가 (적기만 한 것 금지)
- 완료 판정에 그 명령이 그대로 적혔는가
- 핸드오프의 시작 지점이 **실재하는 경로**인가
- 푸시하지 않았는가

## 하지 말 것

- 게이트 레드 상태로 마감
- 검증 안 한 것을 완료로 적기
- PROJECT-STATUS를 길게 쓰기 (상세는 evidence)
- **커밋했다고 푸시까지 하기**

## 다음

- 마감했는데 설계·문서가 미덥다 → 리뷰·심사 스킬(`감사` 계열)로 넘긴다. 단 **마감 전에** 돌리는 게 맞다 —
  마감이 커밋까지 하므로, 뒤에 돌리면 결함이 이미 커밋된 뒤다.
- 이번 세션에 반복 수작업·우회가 있었다 → 회고로 자산화한다. 없으면 넘어간다.
- 판정이 `not-ready`로 닫혔다 → 다음 세션의 시작 지점은 그 미결 하나다. 새 작업을 얹지 않는다.
