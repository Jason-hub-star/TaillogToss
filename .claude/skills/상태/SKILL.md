# /상태 — 읽기 전용 브리핑

## Use When

세션 시작 · 맥락 복구 · "어디까지 됐어". **작업 중간에는 부르지 않는다** — 진입 문서는
마감 때 갱신되므로, 세션 도중 상태는 대화가 이미 알고 있다.

## Steps — 읽을 것 (이 순서, 이것만)

1. `docs/status/PROJECT-STATUS.md` — 완료·다음 걸음·블로커
2. `docs/status/SCOUT.md` 가 있으면 그 `state:` 한 줄
3. 위 둘이 가리키는 문서 **1~3개만**. 그 이상 열지 않는다

**전체 탐색 금지.** 상태를 보려고 코드베이스를 훑으면 브리핑 비용이 작업 비용을 넘는다.
진입 문서가 답을 못 주면 그건 "상태 불명"이고, 그 사실 자체가 보고 내용이다.

## 실행할 것

```bash
git log --oneline -5
git status --short
```

커밋 기록과 작업 트리가 문서보다 최신일 수 있다. **문서와 git이 어긋나면 그것을 보고한다** —
어느 쪽이 맞는지 추측하지 않는다.

## 보고 형식 (5줄 이내)

1. **지금 어디** — 한 줄
2. **마지막에 한 것** — 커밋/문서 기준
3. **막힌 것** — 없으면 "없음"
4. **다음 1개** — 추천은 하나만. 목록을 주지 않는다
5. **어긋난 것** — 문서와 git이 다르면 여기. 없으면 생략

## Verify

- 아무 파일도 고치지 않았는가 (읽기 전용이다)
- 다음 액션이 **1개**인가
- 문서와 git이 어긋났다면 그 사실을 보고했는가

## 하지 말 것

- 파일 고치기 (읽기 전용이다)
- 다음 액션을 3개 이상 나열하기 — 고르는 부담을 넘기는 것이다
- 진입 문서에 없는 것을 추측으로 채우기

## 다음

- 다음 1개가 정해졌다 → 그대로 착수한다. 되돌리기가 비싼 결정이면 착수 전에 `수렴`.
- 상태 불명으로 나왔다 → 새 작업을 얹지 말고 진입 문서부터 복구한다.
- 세션을 닫을 때 → `마감`. 상태는 열 때, 마감은 닫을 때다.
